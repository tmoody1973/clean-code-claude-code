# Developer Handoff Template

Use only relevant sections. Prefer links to repository files and commands that were actually verified.

## Product in one minute

- Purpose
- Intended users
- Primary user journeys
- Current milestone or operating status

## Quick start

- Prerequisites and supported versions
- Install command
- Required environment-variable names and where to obtain values
- Development command
- Test, lint, type-check, and build commands
- Seed or sample-data workflow

## Architecture map

- Entry points
- Major modules and responsibilities
- Dependency direction
- Background jobs or asynchronous flows
- Important architecture decisions and tradeoffs

Use a small diagram only when it makes boundaries or data flow materially clearer.

## Data and integrations

- Databases, schemas, migrations, and storage
- External APIs, authentication, webhooks, queues, and scheduled jobs
- Local emulators or sandbox accounts
- Sensitive-data handling and trust boundaries

Never include secret values.

## Delivery and operations

- Environments
- CI/CD path
- Deployment and rollback
- Health checks, logs, metrics, and alerts
- Backups and recovery where relevant

## Test and quality status

- What is covered
- What is not covered
- Last verified commands and outcomes
- Known flaky or environment-dependent checks

## Known issues and risks

- User-visible defects
- Security or privacy concerns
- Fragile areas and technical debt
- Operational limitations

## Decision log

For each non-obvious decision: context, decision, tradeoff, and date or source when available.

## Recommended next work

Order by product risk and user value. Explain dependencies between items.

## Unknowns for the owner

List questions that repository evidence cannot answer. Do not disguise them as facts.
